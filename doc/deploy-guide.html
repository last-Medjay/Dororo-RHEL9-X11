Dororo Project Manual No. II — Deploying on RHEL 9

Dororo on RHEL 9 — deployment

What's in this folder

File / Dir Purpose
Dororo.x86_64 the executable
Dororo.pck packed assets (Live2D model, UI, scripts)
libgd_cubism.linux.release.x86_64.so Live2D / Cubism native plugin (required)
data_Dororo_linuxbsd_x86_64/ .NET runtime + Dororo.dll (self-contained)
config.ini first-launch settings file — safe to delete
libgd_cubism.linux.debug.x86_64.so only used by the Godot editor; optional in deploy

On the target RHEL 9 box

1. Install system dependencies (one time)

sudo dnf install -y \
    libX11 libXext libXfixes libXrandr libXrender libXcursor libXinerama libXi \
    libGL libEGL fontconfig alsa-lib pulseaudio-libs glib2

(.NET runtime is bundled in data_Dororo_linuxbsd_x86_64/, no separate install needed.)

2. Copy this folder anywhere

# example: extract into your home
mkdir -p ~/dororo && cp -r <this-folder>/* ~/dororo/
chmod +x ~/dororo/Dororo.x86_64

Keep all files together — Dororo.x86_64 looks for the .pck, .so, and data_* folder beside it.

3. Log in to an X11 session, not Wayland

At the GNOME login screen, click the gear icon and pick "GNOME on Xorg". The window-pet features (X11 click-through, always-on-top, global cursor query) rely on Xorg APIs that Wayland doesn't expose. Verify after login:

echo $XDG_SESSION_TYPE   # should print: x11

4. Run

~/dororo/Dororo.x86_64

What works on real RHEL X11 (vs. WSLg where we tested)

Feature WSLg Real RHEL X11
Doro renders ✓ ✓
Click + drag pet ✓ ✓
Settings menu ✓ ✓
Mouse-follow gaze partial (only inside WSL session) full (any cursor position on screen)
Click-through transparent areas off (would break sub-windows on WSLg) can be re-enabled, see below

Optional: re-enable click-through on RHEL

On real RHEL the XShape ShapeInput approach works reliably even with sub-windows. If you want clicks to pass through the transparent areas of the Doro window:

Edit scripts/cs/MouseDetection.cs in the source tree, find the _Ready / _PhysicsProcess overrides, and remove the OperatingSystem.IsWindows() guards so the per-frame click-through toggle runs on Linux too. Then re-export.

(I left it off in this build because WSLg's XWayland routed clicks to the wrong window when ShapeInput was active and Settings was open.)

Troubleshooting

  • Window opens but Doro is invisible: usually means .moc3 didn't get packed. Verify with python3 -c "open('Dororo.pck','rb').read().__contains__(b'MOC3')" → should print True.
  • Transparent window stays opaque-black: no compositor running. GNOME-on-Xorg always has Mutter compositing; bare X without a WM does not.
  • gio: command not found when using trash: sudo dnf install glib2.
  • libgd_cubism.*.so fails to load: check ldd libgd_cubism.linux.release.x86_64.so and install any missing deps (typically libstdc++ from gcc-c++).
